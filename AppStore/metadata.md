## Description (4000)
Rapporteur does one thing: it gets an issue into GitHub before you forget it. The keyboard is ready when the app opens. Type a title, tap Send, and the screen clears for the next issue.

QUICK
• The title field has the focus at launch. There is nothing to tap first.
• Add a description if you want one.
• Tap label chips to add labels. The chips have the colours of your labels on GitHub.
• After Send, the screen is empty again and ready for the next issue.

YOUR REPOSITORIES
• Choose your favourite repositories, public or private.
• Swipe left or right to change the repository.
• Add a repository of another person or organisation by its name.

WORKS OFFLINE
• No connection? Rapporteur keeps the issue in the outbox and sends it when the connection comes back.
• If GitHub refuses an issue, the outbox shows the reason. You can retry, edit or delete the issue.

PRIVATE
Rapporteur talks only to GitHub, with your own account. It has no ads, no analytics and no tracking. The source code is public.

Rapporteur is not affiliated with GitHub.

## Review notes
1. Purpose: Rapporteur creates issues in the user's GitHub repositories. It is for software developers who want to record a bug or an idea quickly.

2. Sign-in: the app needs a GitHub account. It uses GitHub's device flow: the app shows a code, the button "Open GitHub" opens github.com/login/device, and the reviewer types the code there and authorises "Rapporteur". A free GitHub account is sufficient.

3. Instructions: after sign-in, tap "Add a repository" and choose a repository. Type a title, tap a label chip (the chips show only for repositories where the account has write access), and tap the Send button. The issue appears in that repository on GitHub.

4. External services: GitHub only (github.com for sign-in, api.github.com for repositories, labels and issues). No other network requests.

5. Rapporteur is not affiliated with GitHub. It uses the public GitHub REST API.
